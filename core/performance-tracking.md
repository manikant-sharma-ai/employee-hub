# Performance tracking

An employee that cannot say how it is doing cannot get better. Every employee in this hub tracks itself on the calendar and scores itself monthly.

## Why the calendar

The calendar is the one system both sides already trust. It answers "what did I promise, what did I deliver, when" without anyone maintaining a separate dashboard.

## The rhythm

**Before a task** - read the calendar for the next seven days. Commitments already made change the answer: a launch on Friday means a report due Thursday is urgent.

**After a task** - write one calendar event: `[employee] <task> - <outcome>` with the duration. This is the record. If the connector for the calendar is not connected, write the same line in `notes/journal/`.

**Weekly** - one review block, 20 minutes. Count: tasks completed, tasks blocked on a missing connector, tasks that needed rework, and one thing to change next week.

**Monthly** - the scorecard, written into `notes/journal/YYYY-MM.md`.

## The scorecard

| Metric | How to measure |
|---|---|
| Tasks completed | count from the calendar events |
| First-pass acceptance | tasks the person used without asking for a change, over total |
| Blocked on access | count, and which connector would have unblocked each |
| Rework rate | tasks that came back |
| Time per task | median duration from the events |
| Cost per task | where a paid API or model is involved |
| Repeat mistakes | mistakes that also appear in `learnings.md` - should trend to zero |

Four numbers are enough to start. First-pass acceptance is the one that matters most - it is the closest proxy to "would this person hire me again".

## The monthly self-audit

1. Read the scorecard. Identify the worst metric.
2. Read `learnings.md`. Which rule was broken most often?
3. Fix one thing: a reference file, a workflow step, a connector request that should have been made earlier.
4. Write the change and the date in the journal. One change a month compounds; five changes a month do not get made.

## Honesty rule

Report the real numbers, including the bad week. An employee that reports only successes is one whose reports are worthless. If a metric was not measured, write "not measured" - never an estimate presented as a measurement.
