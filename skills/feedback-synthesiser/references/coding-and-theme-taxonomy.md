# Coding and theme taxonomy

Coding is the craft of this role. Done badly it produces eight themes that mean nothing; done well it produces
the one sentence a founder can act on.

## The codebook, built in two passes

**Pass one - open coding.** Read 50-100 items in order. For each, write the problem in the customer's words,
not the system's reason code. Stop when new items stop producing new problems. That is your theme list, usually
8-15 themes for a small business.

**Pass two - closed coding.** Apply the codebook to the whole corpus. Every item gets exactly one primary code
and up to two secondary codes. Anything that does not fit goes to "other" and is inspected at the end.

The "other" bucket is the most valuable part of the first read. If it is above 15-20% of the corpus, the
codebook is wrong and pass one was too narrow.

## The shape of a good theme

| Property | Good | Bad |
|---|---|---|
| Named in the customer's words | "The app logs me out every time" | "Authentication friction" |
| One problem | "Delivery takes 9 days against a 4-day promise" | "Logistics and communication issues" |
| Testable | You could count it again next quarter | You would code it differently tomorrow |
| Actionable by someone | A team exists that could change it | "The market is tough" |
| Not a solution | The problem, not the fix | "We need a mobile app" |

## The starter taxonomy, for a business with none

Adapt, do not adopt. But start here rather than from nothing.

| Code | Covers | Typical channels |
|---|---|---|
| Product defect | Broken, does not work, stops working | Tickets, reviews |
| Not as described | Photo, spec, size chart, ingredients, what arrived | Reviews, returns, tickets |
| Delivery | Late, wrong address, damaged in transit, no tracking | Reviews, WhatsApp |
| Price and value | Too expensive, hidden charges, discount envy | Cancellations, sales calls |
| Payment and billing | Failed payment, refund delay, invoice, GST | Tickets |
| Onboarding | Cannot start, does not understand the first step | Tickets, calls |
| Usability | Cannot find, too many steps, mobile experience | Tickets, reviews |
| Support experience | Slow reply, no reply, repeated explanation | Reviews, tickets |
| Feature gap | Needs something the product does not do | Sales calls, tickets |
| Trust | Is this genuine, will it arrive, data safety | Pre-sales chat, reviews |
| Policy | Return window, warranty, cancellation terms | Tickets, reviews |

Eleven codes cover most Indian SMB feedback. A business with more than twenty is usually coding symptoms.

## Merging and splitting

| Situation | Do | Why |
|---|---|---|
| Two codes always co-occur | Merge, unless a fix would separate them | Co-occurrence is one problem with two symptoms |
| One code is 60% of the corpus | Split by the sub-problem that would be fixed differently | A mega-theme cannot be actioned |
| A code has three items | Keep it, do not merge into "other" | Three customers is a real pattern, and it may grow |
| A code is a proposed solution | Re-code as the problem behind it | Customers describe fixes; you need causes |
| A code names a team | Re-code as the customer experience | "Bad support" is a symptom, not a cause |

## The counting rule

| Rule | Detail |
|---|---|
| Count customers, not mentions | Five messages from one person is one customer |
| One vote per customer per theme | Even if they raised it in three channels |
| Denominator is the corpus | "31 of 214 customers who wrote to us" |
| State the sample | If you coded 400 of 3,000, the percentage is of the sample |
| Never extrapolate to the base | "14% of customers" is wrong; "14% of those who wrote" is right |

## The consistency check

Before publishing, re-code 25 random items blind and compare with the first pass. If fewer than 20 of 25 match,
the codebook is ambiguous - fix the definitions and re-run. This takes twenty minutes and it is the difference
between a read and an opinion.

## Segment cuts that earn their keep

| Cut | What it usually reveals |
|---|---|
| Plan or tier | The cheapest plan complains about limits; the top plan about support |
| Tenure | New customers complain about onboarding; old ones about change |
| Channel of acquisition | Marketplace buyers complain about delivery; direct about product |
| City tier | Tier-2 and tier-3 complain about delivery and COD; metros about price |
| Language | Customers writing in Hindi or Hinglish report different issues than English writers |
| Value | The top 10% by revenue have different complaints, and they are worth weighting |

## Anti-patterns

- **Coding from the reason-code dropdown.** It was set by an agent in eight seconds and is wrong a third of the
  time. Code from the text.
- **Themes named after teams.** "Support issue" tells you who to blame and nothing about what to fix.
- **A codebook that changes every quarter.** Then no theme can be tracked, and the whole point of the second
  read is lost.
- **One theme called "other" with 40% of the corpus.** The read is not finished.
- **Coding by keyword alone.** "Refund" appears in praise and in fury; the sentence decides, not the word.
