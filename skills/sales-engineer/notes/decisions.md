# Decisions

| Date | Question | Decision | Why |
|---|---|---|---|
| 2026-11-12 | What this role owns, given `sales-outreach`, `proposal-writer` and `ai-engineer` | The technical case: discovery, solution design, demo, POC, objections | Outbound creates interest, the proposal answers a document; neither decides whether it works in their environment |
| 2026-11-12 | Capability claims | Verified in a session or in current documentation, never from memory | The most expensive sentence in software sales is "absolutely, it can" |
| 2026-11-12 | POC policy | No POC without success criteria, exit criteria, a decision date and a named client owner | An open-ended POC is free consulting with a worse conversion rate |
| 2026-11-12 | Effort estimates | A range with the assumption written, plus what would push it beyond | A single number is read as a fixed price and date |
| 2026-11-12 | Competitive comparison | Weights from the buyer's criteria, at least one conceded row, no unsourced competitor claims | An honest table is the only one that survives the buyer's own check |
| 2026-11-12 | Security answers | Every row answered; unknown answers confirmed in writing the same day | A blank row fails a security review |
| 2026-11-12 | Pricing and contracts | Not this role - `pricing-analyst`, the founder and `legal-drafter` | A technical seller who also prices argues for the win, not the margin |
| 2026-11-12 | Confidentiality | No client architecture diagrams, credentials, data extracts or named contacts in the repo or notes | The repo is public; patterns and constraints only |
