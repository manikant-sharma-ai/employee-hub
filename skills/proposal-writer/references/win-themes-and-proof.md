# Win themes and proof

A win theme is a claim the evaluator scores, with a proof point attached. Everything else
is an adjective.

## Deriving themes from the criteria

| Step | Do |
|---|---|
| 1 | List the scored criteria with their marks |
| 2 | Rank by marks, then by where the company is genuinely strong |
| 3 | Write one theme per top criterion, as a claim |
| 4 | Attach one proof point to each - a project, a number, a certificate |
| 5 | Test: can the evaluator tick a box with this theme? If not, rewrite it |

Three or four themes. A fifth dilutes the first four.

## Worked example

A facilities-management RFP, criteria: technical approach 30, experience 25, local presence
15, price 30.

| Criterion | Weak theme | Strong theme | Proof point |
|---|---|---|---|
| Technical approach (30) | "We have a robust methodology" | "A 4-hour mobilisation for any site in the NCR, using a 12-engineer bench already on payroll" | Bench list, current mobilisation times, two similar transitions |
| Experience (25) | "Decades of experience" | "Three transitions of 100,000+ sq ft in the last 24 months, all inside the agreed 30-day window" | Completion certificates with dates |
| Local presence (15) | "Pan-India presence" | "Two staffed hubs, Gurugram and Noida, both under 25 km from the sites in scope" | Hub addresses, staff counts, distance map |
| Price (30) | "Competitive pricing" | "A fixed monthly rate for 36 months, with consumables capped at 4% of contract value" | Rate card, cap clause |

Each theme is a number a scorer can write down. None of them could be said by a competitor
without the same evidence.

## The proof-point types

| Type | Weight | Example |
|---|---|---|
| A comparable project with a measured outcome | Highest | "Reduced downtime from 6% to 1.8% over 18 months" |
| A named client reference, contactable | High | "Reference: <role> at <client>, permission given" |
| A certification or audit result | High | "ISO 9001:2015, audited March 2026" |
| A named person with the relevant experience | Medium | "Programme lead: 11 years, 4 similar transitions" |
| A methodology with a tool or template shown | Medium | "The transition checklist, Annexure E" |
| An assertion of capability | Lowest | "We are experienced in this" |

If a theme has only the last type, cut the theme.

## Where themes appear

| Location | How many themes | Form |
|---|---|---|
| Executive summary | All, one sentence each | Claim plus proof, compressed |
| Understanding section | The client's problem, framed by the themes | Narrative |
| Solution section | The themes as section headings where possible | Detailed, with evidence |
| Experience section | Each project tagged to the theme it proves | Case blocks |
| Commercial section | The price theme, with the cap or the fixed rate | Table |
| Cover letter | One line per theme | Short |

Repetition is correct here. An evaluator reading only the solution section must still meet
all the themes.

## The case block

One page per project, five fields:

```
Client: <name, or "a listed FMCG manufacturer in Pune" where confidential>
Scope: <what was delivered, in one sentence, with the numbers>
When: <start and end dates, and whether it was on time>
Outcome: <one measured result, with the baseline>
Relevance: <the requirement this proves, by number>
Reference: <name, role, contact - with permission>
```

The relevance line is the one everyone omits and the one that earns the mark.

## The boilerplate purge

| Boilerplate phrase | Replace with |
|---|---|
| "We are a leading provider of..." | A number: clients, sites, years, volume |
| "Our experienced team..." | Two named people, with years and projects |
| "State-of-the-art technology..." | The actual product, version and what it does |
| "Customer-centric approach..." | The escalation path, with times |
| "Proven track record..." | Three projects with dates and outcomes |
| "Seamless integration..." | The interface, the format, the test plan |

## Losing bids, diagnosed

| Symptom | Likely cause |
|---|---|
| Scored low on technical, high on price | The solution answered the requirement generically |
| Scored high on technical, lost on price | Priced a scope the client did not ask for |
| Disqualified | A mandatory or administrative row missed |
| Shortlisted, lost at presentation | Themes not repeated by the person presenting |
| Lost to the incumbent with no explanation | No differentiation - every theme was an assertion |

Ask for the debrief on every loss. Clients in public procurement often must provide one,
and it is the cheapest market research available.

## Anti-patterns

| Anti-pattern | Cost |
|---|---|
| Themes written before the criteria are read | They score nothing |
| Fourteen themes | None is remembered |
| Theme without a proof point | Reads as an assertion |
| Proof point with no number | "Significant savings" is not evidence |
| The same case study in every bid | Signals a template; relevance is not argued |
| No debrief requested | The same loss, next quarter |
