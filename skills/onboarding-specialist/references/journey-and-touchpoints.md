# The thirty-day journey: designing the path to first value

A journey is not a drip campaign with a diagram. It is the shortest sequence of steps that reliably gets a paying
customer to the milestone, with a named owner on each step.

## The four phases

| Phase | Days | The job | Typical failure |
|---|---|---|---|
| Land | 0-2 | Confirm the purchase, set the expectation, get the one thing you need from them | A generic welcome email that asks for nothing |
| Set up | 1-7 | Remove the blocker: data, access, integration, a decision only they can make | The blocker is never named, so it is never cleared |
| First use | 3-14 | Get the first real object created with their own data | A demo dataset that teaches the buttons and not the job |
| Habit | 14-30 | Repeat the action until it is their process, and widen to the second person | One enthusiast, no second user, silent collapse |

Each phase has one question to answer: *what is the single thing that must be true at the end of it?*

## Step anatomy

Every step carries six fields. If a field is empty, the step is not designed yet.

| Field | Example |
|---|---|
| Trigger | `account.paid` / `3 days since paid and no data imported` |
| Channel | email / WhatsApp / in-app / call / nothing |
| Owner | named role, not "the team" |
| Ask | one action, one link |
| Definition of done | the event that closes the step |
| Stop rule | activation, reply, opt-out, day 30 |

## The kickoff call: when it is worth a human

Offer a call when the contract value justifies it, when setup needs a decision the customer cannot make alone, or
when the customer bought through a channel with high expectation (enterprise, referral, a partner). Do not offer
it when the product is self-serve and the call is a demo the customer did not ask for - a mandatory kickoff for a
₹999 plan is a cost centre that teaches customers to wait for a human.

For those who get one, the call has three jobs and no more: agree the milestone in the customer's words, name the
blocker and who clears it, and book the next contact with a date.

## Capacity maths before design

| Input | Example |
|---|---|
| New accounts per week | 25 |
| Share above the call threshold | 20% = 5 |
| Calls one person can run per week | 8 |
| Available people | 1 |
| Verdict | 5 calls fit; the other 20 accounts get the automated path, and the plan says so |

Designing a journey that assumes calls for everyone produces a backlog of un-called customers and a silent second
tier. The tiering is a decision to write down, not an accident.

## The handover to habit

At day 14 the question changes from "did they set up" to "is anyone else in the account using it". Name the
second-user step explicitly - an invite, a shared report, a colleague copied on the first invoice. Accounts with
one active user churn at roughly the rate of the individual's attention span.

## Anti-patterns

- **The fourteen-email sequence.** Volume is not a journey; most of it is read by nobody and the rest trains the
  customer to ignore the sender.
- **Steps with no owner.** "Marketing sends the welcome" is not an owner when marketing has not agreed.
- **A journey that ends at activation.** The thirty days continue to the handover; stopping at the milestone
  leaves the habit phase unbuilt.
- **Designing for the ideal customer.** The journey must survive a customer who bought at 11pm on a phone and will
  never attend a webinar.
- **Rewriting the journey every month.** One step changes per month, measured, or nothing is learnable.
