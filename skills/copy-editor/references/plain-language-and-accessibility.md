# Plain language and accessibility

Clarity is a copy decision, not a design decision. Most documents that "read
badly" fail on three things: long sentences, hidden actors, and nouns where verbs
belong.

## The measurable targets

| Measure | Target | How to check |
|---|---|---|
| Average sentence length | 15-20 words | Word processor readability stats |
| Longest sentence in a section | 35 words | Search for full stops, count |
| Passive voice | Under 10% of sentences | Count "was/were/been + verb" |
| Jargon per page | Zero undefined | List every acronym and define or cut |
| Reading grade | 9-11 for external, 12-14 for technical | The tool's own score; treat as a guide |

## Plain-language swaps

| Instead of | Write |
|---|---|
| utilise, leverage | use |
| facilitate | help, run |
| prior to | before |
| in the event that | if |
| with regard to | about |
| it is recommended that | we recommend |
| shall (outside contracts) | will, must |
| provide assistance to | help |
| a number of | several, or the number |
| approximately | about |

## Structure that makes a document skimmable

- **The answer first.** The conclusion in the first paragraph; the working after.
- **Headings that state the claim**, not the topic: "Costs rose 18% in Q3" beats "Financial overview".
- **One idea per paragraph**, under six lines.
- **Tables for anything with three or more parallel facts.**
- **Numbered steps for anything a reader will do**, with the actor named.

## Accessibility, the copy half

| Issue | Fix |
|---|---|
| Alt text | Describe the information, not the image: "Bar chart: revenue up 18% from April to September" |
| Link text | "Download the GST filing calendar", not "click here" |
| Tables | A header row, and no merged cells in data tables |
| Colour-only meaning | Say "highlighted in red" as well as showing it |
| Acronyms | Expanded on first use, and in the glossary |
| Direction words | "the section below", not "the section on the right" - screen readers have no right |
| Reading order | The text must make sense in document order, without the layout |

## Inclusive wording, without performance

- **Use the words people use for themselves** - "person with a disability", "Dalit" only where the source uses it.
- **Avoid gendered defaults**: "the manager... they" is correct and unremarkable in Indian business English.
- **Caste, religion and region only when the fact requires it**, and never as a descriptor of quality.
- **Do not euphemise a legal term.** "Terminated" in a policy is not rude; "let go" is ambiguous.

## Anti-patterns

- **Simplified to the point of vagueness.** "We will do better" is plainer and emptier than "we will reply within 24 hours".
- **Alt text that repeats the caption.** Two identical strings help nobody.
- **Readability scores treated as targets.** A score of 8 on a legal notice is a failure, not a success.
- **Stripping every technical term from a technical audience.** Plain language means defined, not removed.
- **Rewriting a quote to be plainer.** Quote as written; paraphrase beside it if needed.
