# Learnings

Durable rules, not stories. One line each, dated when it was learned. Read this at the start of every task.

| Date | Learning | Why it matters |
|---|---|---|
| | | |

## How to fill this

Add a row the first time a reply pattern, a bucket rule or an escalation path proves itself - or fails. Keep it to one line.

- **Reply patterns** - the phrasing that ended a thread in one exchange, and the phrasing that restarted it.
- **Bucket corrections** - comments the triage rules put in the wrong bucket, and the word that would fix it.
- **Channel moves** - when a DM worked and when it read as a dodge.
- **Escalation latency** - who actually responded, and how long it took.

No customer names, no handles, no personal data. The rule, not the incident.
