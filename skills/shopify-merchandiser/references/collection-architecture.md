# Collection architecture

A collection is a promise about what the shopper will find inside it. The catalogue tree
is a promise about the warehouse. Merchandising replaces the second with the first.

## The test

Finish this sentence: "I want something that ______." If the answer is a real shopping
intention - a gift under ₹1,500, a cotton kurta for a wedding, a first pair of running
shoes - it is a collection. If the answer is "our polyester blend", it is a shelf.

## The six collection types

| Type | Built from | Use |
|---|---|---|
| Occasion | what the shopper is buying for | weddings, festivals, back to school, housewarming |
| Recipient | who it is for | gifting, for him, for her, for the parents |
| Price band | a budget the shopper has already set | under 999, 1,000-2,500, premium |
| Problem | the job to be done | monsoon footwear, sweat-proof, easy-iron, travel-size |
| Best-seller | evidence | top 20 by units and by margin, last 90 days |
| New | date | last 30 days, restocked, back in stock |

A healthy store has two or three types in the main navigation and the rest one level down.
A store with all six at the top is a menu nobody reads.

## Navigation rules

- **Three clicks to any product**, measured from the home page.
- **Five to seven items in the top bar.** More than seven and the shopper stops reading.
- **Every collection shows a count** in the admin, and any collection under six products
  is merged or hidden - a thin collection signals a thin shop.
- **No dead ends.** A collection with no products, a filter that returns nothing, a
  pagination that loops - all of them are silent exits.
- **One hero path per season.** The founder's push product gets a named path, and the
  rest of the shop does not compete with it.

## Curated versus automated

- **Automated** - rules on tags, price, stock, date. Cheap to maintain, always current,
  and produces accidental collections ("all products, sorted by newest") that nobody
  curates.
- **Curated** - a manual order chosen by a human. Best for the hero collection, the gift
  edit, and anything where the order is the merchandising.
- **Rule of thumb** - automate the maintenance, curate the order. An automated collection
  with a manually pinned top six is usually right.

## Sorting

The default sort is a merchandising decision, not a setting. Defaults worth testing:

- **Best-selling first** for a broad collection - social proof does the work.
- **Curated order** for a gift or occasion edit - the sequence tells a story.
- **Price low to high** never, unless the shopper chose it. It anchors to the cheapest
  item and hides the margin.

## Seasonal collections

- **Build before the season, not during it.** A festival collection published in the
  first week of the festival has missed the search.
- **Keep the URL.** Reuse last year's collection URL with new products; a new URL each
  year throws away every link and every ranking.
- **Retire, do not delete.** An out-of-season collection set to hidden keeps its history
  and its links.

## Anti-patterns

- **The collection named after the supplier or the fabric.**
- **Fifty collections, each with three products.** It looks like range and behaves like
  a maze.
- **A "Sale" collection as a permanent navigation item**, which anchors the whole shop to
  a discount.
- **A collection built around one SKU** that sells out in a week, leaving an empty page
  and a broken promise.
- **Filters that do not match the catalogue** - a size filter on a one-size product, a
  colour filter with nine variants of "blue".
