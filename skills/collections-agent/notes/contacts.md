# Contacts

| Who | For | How | Notes |
|---|---|---|---|
| <Payer contact per account> | Knowing where the invoice is in their process | | Record who raises the PO, who approves, who releases |
| <Approver per account> | The signature that releases payment | | Ask their name early, not at day 30 |
| <Accounts team per account> | Vendor code, bank details, GRN | | Most delays are resolved here, not with the buyer |
| <Escalation name per account> | When the process fails | | Use it once, at the founder rung |
| <Founder or head of sales> | The relationship call at day 45 | | Bring the chronology, not the frustration |
| <CA> | MSMED delayed-payment position, doubtful-debt provisioning | | Ask before mentioning any statutory position |
| <Lawyer / legal-drafter> | Notices, recovery, limitation periods | | This role briefs; the lawyer acts |
| <Bank or gateway contact> | Payment links, UTR confirmation, settlement failures | | The person who can find a missing payment in an hour |
| <Account owner in sales> | Any live renewal or discount conversation | | Inform before day 30, or the chase contradicts the deal |
| <Billing-support owner> | Failed card retries, refunds | | Different job, different voice - route it |

## Rules

- Record who actually releases the payment, per account. It is the single most useful field in this file.
- Note the payment cycle each customer genuinely runs, not the one in the terms.
- Never store bank account numbers, cheque images, amounts or personal contact details here.
